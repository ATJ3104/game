# ロボファイター制作プロンプト(Claude Code引き渡し用 v3)

## 実行ルール(最初に読むこと)

- **このファイルと同じフォルダに `assets/characters/`(画像16ファイル)がある状態で開始する**
- **ユーザーへの質問は一切せず、本仕様の決定事項に従って最後まで自律実行する。** 仕様に書かれていない細部は「小学生が遊びやすい・シンプル」を基準に自己判断で決めてよい(判断内容はコードコメントに残す)
- 各実装ステップの完了時にビルドが通ること(壊れた状態で次に進まない)
- 最終成果物は「ローカルで動作確認済み + Cloudflare Pagesへデプロイ済みの公開URL」まで。末尾の「公開手順」に従う

## プロジェクト概要

小学5年生の夏休み自由研究として、ストリートファイター2型の2D対戦格闘ゲームを制作する。キャラクターはボクセル/ブロック風の完全オリジナル8体。Webで公開し、PC・スマホ両方でプレイ可能にする。

- ゲーム仮題: 「ロボファイター」(子供が後で改名する可能性あり。タイトル文字列は定数化しておくこと)
- キャラクターのビジュアルは `assets/characters/` に8体分のポートレート画像あり(子供が考案したオリジナルデザイン)
- 既存ゲームのグラフィック・キャラ名・音声は一切使用しない(模倣するのはゲームシステムの構造のみ)

## 画像アセットの扱い(重要)

`assets/characters/` に以下が用意済み:

- `cXX_yyyy.webp` (512x682): ポートレート。**キャラ選択画面のプレビュー、VS画面、勝利画面で使用**
- `cXX_yyyy_thumb.webp` (160x213): キャラ選択グリッドのサムネイル用

**画像は各キャラ1ポーズのみ。戦闘中のキャラクター描画には使わない。** 戦闘中は後述の共通ブロックリグをCanvasでコード描画し、各キャラの配色・特徴パーツをコンフィグで再現する。画像の背景(キャラごとのテーマカラーのブラシエフェクト)は切り抜かず、額装カード風にそのまま使ってよい。

## 技術要件

- **スタック**: HTML5 Canvas + TypeScript(またはバニラJS)。フレームワーク不使用。ビルドは最小限(Vite可、静的出力必須)
- **デプロイ**: Cloudflare Pages に静的サイトとしてデプロイ可能な構成
- **アセット**: キャラポートレート画像(用意済み)以外の画像・音声ファイルは使わない。戦闘グラフィックはCanvas描画、音はWeb Audio APIで合成
- **60fps**: requestAnimationFrame + 固定タイムステップ(可変フレームでゲームロジックが変わらないこと)
- **レスポンシブ**: 画面サイズに合わせてCanvasをスケーリング(内部解像度は固定、例: 960x540)。スマホは横持ち推奨表示を出す

## ファイル構成(目安)

```
/
├── index.html
├── assets/characters/   # ポートレート画像(用意済み)
├── src/
│   ├── main.ts          # ゲームループ、シーン管理
│   ├── characters.ts    # ★キャラ設定8体分(下記の初期データを実装)
│   ├── robot.ts         # 共通ブロックリグの描画・アニメーション
│   ├── fight.ts         # 対戦ロジック(状態、当たり判定、ダメージ)
│   ├── input.ts         # キーボード + タッチ仮想パッド

│   ├── audio.ts         # Web Audio API効果音合成
│   └── scenes/          # タイトル、キャラ選択、対戦、リザルト
└── (Cloudflare Pages用の静的出力)
```

## キャラクターシステム(最重要)

### 共通ブロックリグ

全キャラは同一の「ブロックファイター」リグを使う。ボクセル風の直方体パーツ構成:

- パーツ: 頭 / 髪型・頭部装飾 / 胴体 / 右腕(上腕+前腕) / 左腕 / 右脚(腿+すね) / 左脚
- 全て角丸なしの矩形(fillRect)で描画。輪郭線あり。関節はパーツの回転で表現
- アニメーションは簡易キーフレーム(待機の上下ゆれ、歩行、パンチ・キック、ジャンプ、しゃがみ、やられ、ダウン、勝利ポーズ)
- リグは1つ実装すれば8体全員が使い回せること
- ポートレート画像の雰囲気に寄せるため、頭部装飾(headGear)で個性を出す

### キャラ設定スキーマと初期データ(characters.ts)

```typescript
interface RobotConfig {
  id: string;
  name: string;              // 初期値は下表のとおり。変更はここを書き換えるだけ
  portrait: string;          // ポートレート画像パス
  thumb: string;             // サムネイル画像パス
  colors: {
    primary: string;         // 胴体・脚
    secondary: string;       // 腕・サブパーツ
    accent: string;          // 目・ライト・エフェクト
    skin: string;            // 頭・素肌部分
  };
  headGear: 'mohawk' | 'ponytail' | 'mask_wing' | 'techvisor' | 'spiky' | 'bald' | 'dreads' | 'headband';
  bodyScale: number;         // 0.85(小柄・素早い)〜1.2(大柄・パワー)
  stats: {
    hp: number;              // 900〜1100
    walkSpeed: number;       // 1.0基準の倍率
    jumpPower: number;
    attackPower: number;     // 補正倍率 0.9〜1.15
  };
  special: {
    type: 'projectile' | 'uppercut' | 'dash' | 'spin';
    name: string;            // 初期値は下表のとおり
    shout: string;           // 掛け声(画面に吹き出し表示)
    color: string;           // エフェクト色
  };
}
```

必殺技4アーキタイプが2体ずつになるように配分済み。同タイプ内でも発生・威力・移動量のパラメータで差別化すること。

### 必殺技4アーキタイプ

1. **projectile(飛び道具)**: エネルギー弾を前方に発射。弾速・サイズはキャラ差分
2. **uppercut(昇竜)**: 上昇しながらの対空攻撃。無敵時間わずかにあり
3. **dash(突進)**: 前方に高速突進しながら攻撃。ガードされると隙大
4. **spin(回転)**: その場で多段ヒットの回転攻撃

バランス目安: 威力は通常技の2〜2.5倍。発生・硬直で個性を出す。

## 対戦システム

### 操作

- 移動(前後歩き)、垂直/前方/後方ジャンプ、しゃがみ
- 攻撃: パンチ(弱・発生早い)、キック(強・発生遅い)。立ち/しゃがみ/ジャンプで技が変わる(最低限: 立ちP、立ちK、しゃがみP、しゃがみK、ジャンプK)
- **ガード**: 後ろ方向ホールドで自動ガード(しゃがみガードあり)。削りダメージなし(子供向けに簡略化)
- **必殺技: 専用ボタン方式**。コマンド入力は不採用。ゲージ(時間+攻撃ヒットで蓄積)が満タンのとき必殺技ボタンで発動。ゲージは画面下に表示

### キー割り当て

- **1P(PC)**: A/D=移動, W=ジャンプ, S=しゃがみ, J=パンチ, K=キック, L=必殺技
- **2P(PC)**: ←→=移動, ↑=ジャンプ, ↓=しゃがみ, 1=パンチ, 2=キック, 3=必殺技(数字キー上段)。同時押し衝突がないか確認すること
- **スマホ(タッチ)**: 左に仮想十字パッド、右にP/K/必殺の3ボタン。ボタンは十分大きく(最小64px)、マルチタッチ対応必須。スマホは1P vs CPUのみ

### ラウンド・勝敗

- 99秒タイマー、2本先取(最大3ラウンド)
- KO演出(スローモーション+"K.O."表示)、タイムアップ時は残HP判定
- ラウンド開始時 "READY... FIGHT!" 表示

### ヒット演出(手触り重視)

- ヒットストップ(ヒット時に両者数フレーム停止)
- ヒットスパーク(パーティクル)、ダメージ時の点滅
- 強攻撃・必殺技ヒット時の画面シェイク
- 必殺技発動時に掛け声(shout)を吹き出しで表示

### 当たり判定

- 矩形hitbox/hurtboxの単純判定。技ごとに発生フレーム・持続・硬直を定義
- めくり・投げ・連続技補正などの高度なシステムは不要

## CPU AI

- 3段階難易度(よわい / ふつう / つよい)
- 距離に応じた行動テーブル + ランダム重み付けのステートマシン
  - よわい: 反応遅い、ガードほぼしない、必殺技をあまり使わない
  - ふつう: たまにガード、距離に応じた技選択
  - つよい: 高反応、対空、ゲージが溜まると必殺技を積極使用
- フレーム単位の完全反応(人間に不可能な反応)は禁止。反応遅延を必ず入れる

## 画面フロー

1. **タイトル**: ゲームロゴ(テキスト装飾)、「1P vs CPU」「2P対戦」選択。スマホでは2P対戦を非表示または「PCでプレイしてね」表示
2. **難易度選択**(CPU戦のみ)
3. **キャラクター選択**: 8体を2x4グリッドでサムネイル表示(SF2風)。カーソルで選択、選択中キャラは右側に**ポートレート画像**+名前・タイプ・必殺技名を大きく表示。2P時は両者が選択
4. **VS画面**: 両者のポートレートを左右に対面配置して2秒表示
5. **対戦画面**: 上部にHPバー(左右)+タイマー、下部に必殺ゲージ。背景はシンプルなステージ(空+地面+遠景シルエット程度を3〜4種、コード描画)。ステージの差し色は選択キャラのテーマカラーに寄せると統一感が出る
6. **リザルト**: 勝者の**ポートレート画像**+勝利ポーズリグ+名前表示、「もういちど」「キャラ選択へ」「タイトルへ」

## サウンド(Web Audio API合成)

- 効果音: パンチヒット、キックヒット、ガード、ジャンプ、必殺技発射、KO、カーソル移動、決定
- 全てオシレーター+エンベロープで合成(矩形波・ノイズ)。レトロゲーム風で良い
- BGMは任意(簡単なループがあれば尚可、なくても減点しない)
- スマホの自動再生制限対策: 初回タップでAudioContextをresumeすること

## 実装順序(この順で進めること)

1. ゲームループ + Canvas スケーリング基盤
2. ブロックリグ描画 + 待機/歩行アニメーション(1体で確認)
3. 入力システム(キーボード → タッチは後)
4. 対戦ロジック(移動、ジャンプ、通常技、当たり判定、HP)
5. ガード、必殺技4アーキタイプ、ゲージ
6. ラウンド制、KO演出、ヒット演出
7. CPU AI(3段階)
8. 画面フロー(タイトル→選択→VS→対戦→リザルト、ポートレート画像組み込み)
9. 8体分のキャラ設定投入(上記テーブルの初期データ)
10. タッチ操作 + スマホ最適化
11. サウンド
12. 仕上げ(バランス調整、ビルド、デプロイ ※下記「公開手順」)

各ステップ完了ごとに動作確認できる状態を維持すること。

## 公開手順(実装完了後に必ず実行)

1. `npm run build` で静的出力(`dist/`)を生成。`assets/` が出力に含まれることを確認
2. ローカル確認: `npx serve dist`(または `npx vite preview`)を起動し、curl等でトップページが200を返すことを確認してから終了
3. Cloudflare Pagesへデプロイ:
   ```bash
   npx wrangler pages project create robo-fighter --production-branch=main 2>/dev/null || true
   npx wrangler pages deploy dist --project-name=robo-fighter
   ```
4. デプロイ成功時に出力される公開URL(`https://robo-fighter.pages.dev` 等)をユーザーに報告する
5. wranglerが未認証でデプロイに失敗した場合のみ、`npx wrangler login` の実行をユーザーに依頼し、認証後に再デプロイする(質問禁止の例外はこの1点のみ)

## 完成時セルフチェック(全て自分で確認してから完了報告すること)

- ビルドがエラー・警告なしで通る
- `dist/` 内にポートレート画像16ファイルが含まれる
- characters.ts の8体の名前・技名・掛け声が本仕様の表と一致する
- タイトル→キャラ選択→VS→対戦→リザルトの遷移がコード上で全て繋がっている(到達不能なシーンがない)
- タッチ操作のイベントリスナーに `passive: false` と `preventDefault` が設定され、スマホでのスクロール暴発を防いでいる
- AudioContext が初回ユーザー操作で resume される実装になっている
